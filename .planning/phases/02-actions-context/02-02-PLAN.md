From CONTEXT.md (LOCKED USER DECISION - Two-step prompt pattern):
- "Two-step prompt pattern — Agent first responds with speak action + target, then gets reprompted for message content"
- "Action XML format (step 1) — `<Action name="speak"><target>Alice</target></Action>`"
- "Message collection (step 2) — Separate prompt asking for freetext message content"

CRITICAL CLARIFICATION (from checker):
The "two-step" pattern is LLM INTERACTION only:
- Step 1: LLM responds with action selection (XML: `<Action name="speak"><target>Alice</target></Action>`)
- Step 2: LLM gets prompted for message content (freetext)
- BUT the action's handle() method receives BOTH target AND message in action_data

The simulator/agent loop orchestrates this:
1. Receives action selection with target
2. Prompts agent for message content
3. Calls action.handle() with BOTH target AND message

The action class should:
1. Accept `message` parameter in action_data
2. Create TalkToEvent with the message
3. Deliver message via `target.add_env_feedback(formatted_event)`
4. Return result with message: `{"to": target_name, "message": message}`
